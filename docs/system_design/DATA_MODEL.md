# Data Model

本文定义主机程序各模块之间交换的数据：每种数据包含什么、由谁产生、谁使用、以什么方式传递。它是模块之间的契约，具体的编码格式和存储方式属于 Implementation。

所有运行时数据使用同一个单调递增的时间基准，单位为秒，称为系统时间。绝对的日期时间只用在需要和外部对齐的地方，例如录制。

## 数据流向

| 数据 | 产生者 | 使用者 | 传递方式 |
|---|---|---|---|
| 压力帧 | 设备连接 | 感知 | 逐帧交付 |
| 垫面快照（压力图、垫面状态、特征） | 感知 | 声音化、控制接口、录制 | 最新值 |
| 垫面事件 | 感知 | 声音化、录制 | 事件队列，使用者取走自上次以来的全部事件 |
| 节拍 | 时钟 | 声音化 | 固定节拍 |
| 声音意图 | 声音化 | 声音引擎、录制 | 最新值，每拍整体替换 |
| 模式状态 | 声音化 | 状态中心、控制接口 | 最新值，每拍整体替换 |
| 灯光意图 | 声音化、录制（系统提示层） | 灯光引擎 | 最新值 |
| 配置 | 配置文件 | 各模块 | 启动时读取 |
| 设置 | 状态中心 | 各模块 | 读取 + 变化通知 |
| 运行状态 | 各模块、系统监测 | 状态中心、控制接口 | 最新值 + 变化通知 |

最新值的意思是：产生者用新数据覆盖旧数据，使用者需要时读取当前这一份，两边不互相等待。事件队列用于不能丢失的离散事件，使用者每次取走全部积累的事件。

## 区域

垫面被划分为 224 个区域，是感知能分辨的最小单位。环从内到外编号 0 到 7；角度以 12 点方向为 0，顺时针增加。第 0、1 环每环 16 个区域，第 2 到 7 环每环 32 个区域；内两环每个区域的角度跨度是外环的两倍，并且与外环交错半个外环区域：每个内环区域的中心正对一个外环区域的中心，两条边界分别落在相邻两个外环区域的中线上。这来自传感器图案（`SoundMat/system/sensor/sensor_design/final/fabric_slices.svg`）：第 1 环与第 2 环之间的间隙以内，只有隔一个的扇区电极继续向内延伸，内部的分割线位于扇区中线上。第 0、1 环的划分完全相同，彼此不交错。

每个区域有一个稳定的标识（环号 + 环内序号），以及几何描述：中心角度、角度跨度、内外半径。声音化和空间化使用几何描述，不依赖接线顺序或环内序号的计算方式。区域划分属于传感器设计，变化时只需更新这份几何描述。

## 压力帧

压力帧是控制器扫描一遍传感器得到的原始读数，按物理接线排列，附带接收时刻和序号。它只在设备连接和垫面信号之间流动，其他模块不读取原始帧。

## 压力图

压力图是垫面信号的输出：每个区域一个归一化压力值，0 表示没有压力，1 表示满量程（由配置给出）。它已经完成校准和坐标对齐，与传感器的接线、内两环的物理合并方式无关。压力图附带产生时刻和来源帧的序号。

## 垫面状态

垫面状态是垫面解读在压力图之上的判断：

1. 被占用的区域集合，即判断为有石头的区域。
2. 每环被占用的区域数。
3. 控制区压力：控制区内压力的总和。控制区由当前模式在加载时声明（例如 Jam 使用第 0、1 环），没有声明时不计算。

占用判定带有去抖：一个区域需要稳定超过阈值一段时间才算被占用，稳定低于阈值一段时间才算释放，阈值和时间都来自配置。垫面状态附带产生时刻。

## 垫面事件

垫面事件描述占用的变化：放下（某区域从未占用变为占用）和拿起（反之）。每个事件包含区域标识和发生时刻。事件按发生顺序进入事件队列，使用者取走后才会被移除。新的事件类型（例如挪动）作为特征的产物加入时，同样进入这个队列。

## 特征

特征是从垫面状态派生的附加信息，由可插拔的特征提取器计算，以名称标识放在垫面快照中。使用者只读取自己需要的特征；缺少某个特征时不影响其他数据。每加入一种特征，需要说明它服务的 Design 要求。

## 节拍与时间窗

时钟按固定节拍驱动声音化，每一拍提供：节拍序号、当前系统时间，以及一个前瞻时间窗（从当前时刻到当前时刻加上提前量）。需要音乐时间的模式（速度、小节、拍位）自己维护从系统时间到音乐时间的换算，时钟只提供统一的时间基准。

## 声音意图

声音意图是声音化每拍给出的完整描述，由三部分组成。

**持续声部**是此刻应该存在的声音的集合。每个持续声部包含：

1. 稳定标识：由模式指定，同一个声音在不同拍之间保持相同标识，声音引擎据此判断是新增、保留还是移除。
2. 声源：引用一个音色或一段声音素材。
3. 总线：声部汇入的混音总线，即它所在的环；不属于任何一环的声音（例如 Jam 的和声铺底与鼓）汇入模式声明的其他分组总线。
4. 参数：音量、音高、滤波等，以及淡入淡出时长。
5. 位置：垫面上的角度和半径，或者标记为不定位（充满整个空间）。
6. 优先级：声部超出预算时决定谁让位。
7. 类别：声部预算可以按类别分别限制（例如 Jam 扫描触发的旋律与贝斯属于 `melodic`）；不属于任何受限类别时只计入总数。

**定时事件**是前瞻时间窗内要发生的单次声音。每个事件包含唯一标识、准确的发生时刻、声源、总线、参数、位置、优先级和类别。模式保证每个事件只交出一次，声音引擎再按标识去重。

**全局参数**作用于整个模式的输出，例如总音色、混响、整体音量。

声音意图每拍整体替换上一拍的意图。声音引擎只关心意图与实际在响的声音之间的差异，所以模式可以每拍从头计算，不需要记住自己上一拍发过什么。

## 灯光意图

灯光意图是一组按优先级排列的灯光层。每一层为灯环上的每个逻辑位置给出颜色和不透明度；逻辑位置 0 在 12 点方向（0°），顺时针编号，总数即配置中的灯珠数量。灯光引擎从低到高合成各层，再施加物理对齐偏移。声音化产生底色、预览、命中等层；录制倒计时等系统提示作为最高优先级的系统层，由提出者单独提供。

## 模式状态

模式状态是模式每拍交出的一小段供人看的描述，与意图一起产生：一行状态文字（例如 Jam 的"第 3 段 C · 0:44 / 2:08"、空闲时的"压住中间两环开始"），以及可选的一个数值读数（例如"Lo-Fi 45%"）和走带状态。它只用于控制台显示和录制信息，不影响声音和灯光。

## 编排

编排是声音化的内容数据，包含：标识、显示名称、使用的模式、每环在控制台上显示的名字、引用的音色和声音素材，以及模式所需的具体内容（例如每环的声音编排表、和弦进行与旋律表）。编排对素材和音色只做引用：引用以声音素材库或音色库内的相对位置表示，不包含素材本身。加载编排时检查引用是否存在，缺失项报告给系统监测。

编排可以声明一组可调参数及其范围，作为将来现场调整的入口（预留，当前不实现）。

## 配置与设置

主机程序的参数分为两类，区别在于是否随场地和使用而变化。

**配置**描述硬件和系统本身，部署前测定，写在仓库的配置文件里，随部署分发；程序启动时读取，运行中不变，控制台只读显示。改配置就是改仓库、重新部署。

1. **垫面**：接线到区域的对应关系（扇区镜像、整体旋转偏移）、压力满量程、占用阈值与去抖时间。
2. **灯光**：灯珠数量、物理对齐偏移、刷新率。
3. **声音**：声部预算（总数及按类别的上限）、期望的采样率与输出设备、声音化节拍频率、声音素材的内存预算、输出延迟与迟到容限、交叉淡化时长。

控制区的启动阈值、Lo-Fi 映射范围、播放中是否预听，属于 Jam 的编排数据，同样是固定的内容，不在运行中调整。

**设置**随场地和使用而变化，由状态中心持久保存，可以在控制台修改，修改后立即通知使用者：

1. **声音**：音箱布局（声道数及每只音箱的方位）、垫面朝向偏移、总音量。
2. **运行**：默认编排、声音素材库位置。
3. **录制**：保存位置、是否录制分轨。
4. **预留**：开放时段、音量上限。

网络与系统服务的配置不属于这里，随部署一起管理。

## 运行状态

运行状态是各模块报告的当前情况，由状态中心汇总，供控制接口显示：

1. 控制器链路：是否连接、实测传感帧率、校验错误数。
2. 音频链路：音频服务、输出设备、合成器服务是否正常；合成器服务实际使用的输出设备、采样率、声道数与缓冲设置；音色与素材加载情况及缺失项；卡顿次数、运算负载、在响声部数、总输出各声道的电平，以及各环总线各声道的电平（控制台垫面页的每环电平）。
3. 机器：温度与降频、内存、剩余空间、运行时长。
4. 网络：当前网络、地址、Tailscale 状态。
5. 当前：编排与模式、模式状态、是否使用虚拟垫子、录制状态。
6. 日志：最近的警告与错误。

每一项带有更新时刻；超过一定时间没有更新的项显示为未知，而不是沿用旧值。

## 录制会话

一次录制会话包含：会话标识、编排与模式、开始时刻（系统时间和绝对时间）、打板时刻、结束时刻，以及产出文件的清单（总输出、各分轨、会话数据）和开始时的设置快照。会话数据按时间顺序记录压力图、垫面事件、声音意图和灯光意图，每条都带系统时间。
