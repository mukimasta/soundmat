### 2026-05-31

### 2026-06-03

### 2026-10-14

1. 声音素材移出仓库，放到 `SoundMat/sound/`，原来的 `sc/assets/samples` 改为指向它的符号链接，`.gitignore` 随之修改。
2. 查明网页 Mat 页卡顿的原因：灯光每次变化都会让浏览器重算 256 个隐藏石头和 108 颗灯各自的模糊滤镜。改为只给已放下的石头加滤镜、灯环整体共用一个滤镜后，帧率从约 5 帧升到 120 帧（实测）。

### 2026-10-17

1. 开始按新架构重写主机程序和网页控制台，分阶段推进，每个阶段都能用虚拟垫子和不发声的记录型声音引擎在没有硬件的环境里运行和测试。第一版代码从工作区移除，保留在 git 标签 `v1-ece546`（提交 `5d2260b`，课程期末展示的版本）。
2. 第一阶段完成：配置文件、224 区几何、垫面解读（占用判定、去抖、事件、控制区压力）、虚拟垫子、状态中心、控制接口（WebSocket 推送 + HTTP 命令），以及按设计稿实现的控制台垫面页。控制台首页按设计稿改为垫面（`DECISION.md` 第 8 条）。
3. 发现第一版没有逐区去抖，只有控制区松开时 0.1 秒的保持；新版的去抖时间先取放下 40 ms、拿起 80 ms，需要上真机调。
4. 第二阶段完成：时钟、意图、模式生命周期与交叉淡化切换、声音引擎核心（对账、声部预算与让位、定时事件去重与迟到、合成器服务重启后重建并重新对账、空间化公式），全部在不发声的记录型引擎上测试。实现时补上了文档的一处空缺：Jam 的和声与鼓不属于任何一环，声部因此带一个"总线"字段，模式可以在环总线之外声明分组总线（`SOUND_ENGINE.md`「混音结构」）。
5. 第三阶段完成：编排文件格式与读取、《京都岚山》转换为新格式、素材库（内存预算、引用计数、缺失报告）、Ambient 模式、设置的持久化，以及控制台的底部导航、当前编排卡片、编排面板、菜单与设置面板。云端没有声音素材，14 个素材全部报告缺失，程序照常运行、测试照常通过。
6. 第四阶段完成：Jam 模式与《Lo-Fi Loop · Progression 1》编排。第一版的理论、时间方案、曲式、扫描命中与灯光移植过来，输出改为意图；扫描命中、鼓和小节线的时刻在前瞻时间窗内直接解出，不再落在帧上。为了让和声与鼓同样准时，持续声部增加了可选的开始时刻（`DATA_MODEL.md`「声音意图」）。
7. 第五阶段完成：设备连接（选口、S/L 帧、等待就绪、断线重连、实测帧率）、垫面信号（第一版的校准与坐标对齐）、灯光引擎（60 Hz 分层合成、系统提示层、灯带偏移）和控制台的灯环预览，用模拟 ESP32 测试。移植坐标对齐时发现，第一版的内环经过两次镜像，实际上没有被镜像，而外环是镜像的；新版照搬，留待真机核对。
8. 第六阶段完成：scsynth 实现（带时间戳的 OSC bundle、每个模式实例一套混音结构、交叉淡化、空间化增益、重启检测与重建、节点结束通知、电平回报），第一版音色移到 `instruments/` 并改为按 2、4、8 声道编译的多声道输出。云端装上 JACK（dummy 驱动）和 SuperCollider 后，用真实的 scsynth 跑通了 Ambient、Jam、杀掉并重启 scsynth 后的自动恢复。调试中发现两件事：模式总处理的低通截止设在 20 kHz 时会失稳输出无穷大，改为与第一版相同的 18 kHz 上限并在默认值时旁路；主机程序重启时 scsynth 里上一次的节点还在，接上时先清空节点树。
9. 第七阶段完成：系统监测（音频服务、声卡与实际输出设备、合成器服务、卡顿、机器、网络）和状态指示规则，控制台按设计稿做出完整的看板（总体结论、三个状态指示、各组详细信息、逐声道测试音）、垫面页的问题提示条和看板入口上的小点。在云端的 JACK dummy 环境里，监测正确地把"输出到虚拟设备"判为异常。
10. 第八阶段完成：录制（空间检查、倒计时与打板、合成器服务内部录下总输出和分轨、会话数据、录制信息、打包下载）和控制台的录制按钮、倒计时、已录制列表。用真实 scsynth 录音验证了打板提示音落在录音第 3 秒（误差 30 毫秒以内）。分轨在模式总处理之前，实测会超过 0 dBFS，所以分轨用 32 位浮点、总输出用 24 位。至此重写的八个阶段全部完成，等待在 Mac 上试听、在 Pi 上部署验证。
11. 在 Mac 上评审后修正了四处：编译脚本只在 Linux 上设置 Qt 的 offscreen 平台（macOS 版 sclang 不带这个插件，会直接退出）；主机名已带 `.local` 时不再追加；底部面板可以按 Esc 关闭，焦点随面板进出；没有音频时录制不建 `stems/`。同时发现设置文件会把没改过的默认值也写进去，声音素材库的位置因此被写死、`SOUNDMAT_SOUND` 失效，改为只保存改过的项。README 的快速开始按 macOS 逐步核对后重写。
12. 第九阶段（在本地完成）：灯环预览、电平条和看板。实测控制台每秒只收到约 23 帧灯环数据：灯光引擎是 60 Hz，但预览被限到 30 Hz，控制接口又按 30 Hz 轮询，两边节奏错开会丢帧。改为预览与灯光同频，推送由数据变化唤醒，颜色编码成十六进制字符串（每帧约 650 字节）；控制台把灯环拆成单独的组件，每帧只重画灯珠。之后又发现声音化和灯光引擎两个 60 Hz 时钟之间也在错拍（每秒 47 份新灯光意图只有 39 份到达预览），改为新意图到达时立刻合成，修正后两者一致。电平条改为一层一根、由编排声明分组（`DECISION.md` 第 9 条），Lo-Fi 的和声和鼓第一次显示出来。看板新增"节奏"卡（各条链路的实测与期望帧率、节拍超时、迟到），以及连接类型、自建热点上的设备数、主机程序运行时间与自动重启次数、程序版本、还能录多久；最近 1 分钟节拍晚到超过 50 ms 有 3 次以上或有迟到、或主机程序一小时内被自动重启过。最初按"节拍超时"（某一拍晚到挤占了下一拍）报警，在 Mac 上开着 scsynth 实测每分钟 79 次，而节拍率仍是 60、迟到为 0：这些超时只是线程调度和 Python 全局锁带来的几毫秒延迟，有前瞻和输出延迟兜着，不影响声音，所以改为按真正可能让声音迟到的延迟判断，声音一项记为需要注意。
13. 开发机上恢复一条命令运行：`uv run soundmat` 先看配置的端口上有没有 scsynth，有就连，没有就自己启动、退出时一起关掉；树莓派上仍由 systemd 管 scsynth，在 systemd 下从不自己启动。启动时打印控制台的本机和局域网网址。顺带发现连真实 scsynth 的两个测试在开发机上会连上正在试听的 scsynth、清空它的节点树，改为需要显式打开。
