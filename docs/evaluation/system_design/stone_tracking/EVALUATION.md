# 石头跟踪

### Claim

垫面解读把一颗石头当作一颗石头（`system_design/DATA_MODEL.md`「垫面状态」）：放在哪就在哪，骑在分界线上不丢、不算成两颗，静止时不闪；拖动是挪动，不是拿起加放下；别处放石头带来的串扰不会让它被当成拿起。

### Scope

System：真实录下的压力图经过当前的垫面解读（石头检测、跟踪、去抖、串扰补偿），和按区判断的旧做法对比。不含声音和灯光；不含实机上的完整帧率（见「限制」）。

### Method

用 `scripts/replay_mat.py --legacy` 回放控制台的录音：

1. 2026-10-18 两段真实游玩（Pi 3B，Lo-Fi 13 分钟、冥想 4 分钟，几个人一起玩，没有标准答案）；
2. 2026-10-20 三段有标准答案的测试（Pi 5）：200 g 砝码沿直径从一头拖到另一头再停在外环，100 g 沿同一条直径拖过去后拿起（200 g 压在它的导电条上）；两颗砝码先后沿第 1 环、第 0 环拖一圈，最后把一直压在 7:8 的 200 g 拖进中心再绕第 0 环一圈；9 颗石头静止摆放。

旧做法有两种：`v1` 是第一版（单区阈值 500，放下 40 ms、拿起 80 ms），10-18 演出时就是它；`zones` 是 4d2b1a0 的按区判断（外环 245、内两环 185，拿起低于 0.67 倍，各 80 ms）。

### Metric / Oracle

1. 有标准答案的测试：放下、拿起的次数和位置与实际一致，拖动全程是同一颗石头。
2. 真实游玩：一颗石头不到 0.5 秒就被拿起（"闪"）的次数；拿起后 1 秒内在同一个区或相邻的区又放下（读数掉下去又回来、或拖动被拆开）的次数；石头寿命的中位数。前两项越少越好；寿命没有标准答案，作为对照。

### 结果（2026-10-20）

真实游玩：

| | Lo-Fi 13 分钟：石头 / zones / v1 | 冥想 4 分钟：石头 / zones / v1 |
|---|---|---|
| 放下 | 220 / 715 / 599 | 108 / 261 / 252 |
| 闪（< 0.5 s） | 16 / 187 / 222 | 1 / 31 / 59 |
| 拿起又放下（1 s 内、同区或相邻） | 16 / 311 / 308 | 10 / 66 / 108 |
| 寿命中位数 | 23.8 s / 3.4 s / 1.0 s | 25.0 s / 10.6 s / 2.6 s |
| 挪动 | 414 | 116 |

有标准答案的测试：

1. 沿直径拖砝码：放下 2 次、拿起 1 次，与实际一致（`zones` 29 / 28，`v1` 25 / 24）。200 g 穿过中心、停在外环被 100 g 的串扰拉低，全程是同一颗石头。
2. 绕内两环：放下 4 次，实际是 2 颗砝码。多出的两次都来自硬件：一次是 135° 那根断掉的导电条（约 0.6 秒读不到），一次是 100 g 在最内环几个区几乎没有读数（约 2 秒）。最后把 200 g 从外环拖进中心再绕一圈，全程是同一颗石头、45 次挪动。
3. 9 颗石头静止：9 颗（包括压到最内环边缘的中心那颗），其中几颗骑在分界线上、两边都低于阈值；`zones` 认成 14 个区，`v1` 只认出 8 个、还有 3 次拿起。

判断：在这几段录音的范围内，Claim 成立。真实游玩里没有标准答案，"闪"和"拿起又放下"减少是旁证，不能排除漏判（把挨着的两颗认成一颗）；逐个查看了被标记为可疑的情况，都是落地时溅到旁边、手掌压内圈控制区、或者真的被拿起换了位置。

### 限制

1. 录音里的压力只有约 10 帧/秒（实机约 28 帧/秒），时间相关的判断（放下 80 ms、换主区 150 ms、拿起 80 / 400 ms）在录音里被量化到 0.1 秒。
2. 10-18 的录音是 Pi 3B、内两环坐标改正之前，回放时换算到现在的坐标；当时的阈值和这次无关，回放只用压力图。
3. 串扰补偿系数 7 是 19 次"同一根导电条上新放一颗"的中位数（四分位 5.6–11.3），离散很大。

### 待验证

1. 在实机的完整帧率下，骑线、挨着先后放两颗、拖过环缝和中心、在同一根导电条上压重石头，看事件是否与实际一致。
2. 两颗石头同时放在相邻的两个区会被认成一颗（压力图里分不出来）；这种情况在真实游玩里有多常见。
3. 内两环灵敏度只有外环的一半、各区之间也差两三倍，轻石头在最内环仍可能认不出来；是否需要逐区校准。
