# Host Program

本文说明主机程序（Python 包 `soundmat/`）当前的工程实现：怎样运行、模块落在哪些文件、线程怎样分工、配置怎样读取，以及几处需要知道的实现约定。模块职责见 `ARCHITECTURE.md`，模块之间的数据契约见 `system_design/DATA_MODEL.md`，控制接口协议见 `CONTROL_API.md`，控制台见 `CONSOLE_APP.md`。

## 运行

```bash
uv sync                         # 安装 Python 3.12 与依赖
uv run python scripts/compile_instruments.py   # 编译音色（需要 SuperCollider）
scripts/scsynth-dev.sh &        # 开发机上启动合成器服务
uv run soundmat --virtual       # 用虚拟垫子运行，控制台在 http://localhost:8000
uv run pytest                   # 测试
```

主机程序默认连接本机的 scsynth（见 `SYNTH.md`），`--no-synth` 改用只记录指令、不发声的声音引擎。不带 `--virtual` 时连接控制器：`--port-serial` 指定串口，默认 `auto` 自动选择（规则见下文「设备连接」）。`--virtual` 用虚拟垫子代替控制器；`--config` 指定其他配置文件；`--data-dir` 指定本机数据目录（设置文件 `settings.json` 和录音，默认是程序目录下的 `data/`，树莓派上是 `/home/soundmat/data`）；`--host`、`--port` 覆盖控制接口的监听地址。控制台需要先在 `console/` 下构建（`npm ci && npm run build`），构建产物由控制接口直接提供；开发控制台时用 `npm run dev`，Vite 把 `/api` 和 `/ws` 转发到 8000 端口。

## 线程与数据交换

每种节奏一个线程，控制接口运行在 uvicorn 的 asyncio 事件循环里（主线程）。线程之间只通过 `exchange.py` 的容器交换数据：`Latest` 保存最新值，带版本号，读的一方据此判断有没有新值；`EventHub` 为每个订阅者维护一个 `EventQueue`，订阅者每次取走积累的全部事件，所以多个使用者（声音化、录制）互不影响，事件不会丢失。

当前的线程：

1. **虚拟垫子**（`virtual-mat`）：每秒 60 次产生压力图，在本线程里调用 `Perception.feed` 完成垫面解读，发布快照和事件。真机上由设备连接的读取线程调用同一个入口。
2. **声音化**（`sonification`）：`BeatClock` 每秒 60 拍（配置 `sound.tick_hz`）。每拍取走垫面事件、读取最新快照、调用所有模式实例（切换期间新旧两个），把声音意图交给声音引擎，再处理合成器服务的通知、释放淡出完毕的实例。声音引擎不是线程安全的，只在这个线程里调用；切换编排的请求从其他线程放进队列，在下一拍开始时执行。某一拍的计算超过节拍间隔时不补拍，直接跳到当前时刻，并计入 `BeatClock.overruns`。
3. **设备连接**（`device`）：真机上读串口，每收到一帧 S 帧就在本线程里完成垫面信号和垫面解读（代替虚拟垫子线程）。灯光帧由灯光线程直接写串口，写入加锁。
4. **灯光**（`light`）：每秒 60 次（配置 `light.refresh_hz`）读取最新的灯光意图和系统提示层，合成后写给设备连接，并以 30 次/秒更新控制台的灯环预览。
5. **系统监测**（`monitor`）：每秒采集一次并写入状态中心，较慢的探针（journal、nmcli、tailscale）每 10 秒一次。
6. **会话数据写入**（`session-writer`）：录制期间把会话数据逐行写进文件，不阻塞节拍线程。
7. **主线程**：uvicorn 与控制接口。

状态中心的订阅回调在修改者的线程里执行；控制接口在回调里只用 `loop.call_soon_threadsafe` 把变化交给事件循环，再由每个 WebSocket 连接自己的推送任务发出。

## 配置

`config/soundmat.toml` 在启动时读取一次。压力相关数值在文件里是 ADC 原始读数（满量程 4095），`MatConfig` 换算成归一化压力（读数 / 4095）。文件里出现未知的段或键时启动报错，避免拼错的键被悄悄忽略、装置带着默认值运行。控制台"配置 · 只读"一栏的文字由 `Config.describe()` 生成。

## 区域几何的约定

区域角度沿用第一版的逻辑坐标，因为扇区偏移 4 和灯带偏移 101 都是在这个约定下校准的（见 `DECISION.md` 第 7 条）：外环第 j 区的中心在 j × 11.25°；内环第 j 区就是第一版的第 2j+1 扇区，中心在 (2j+1) × 11.25°。区域的全局序号从第 0 环第 0 区开始依次递增（第 0 环 0–15，第 1 环 16–31，第 2 环从 32 开始，每环 32 个），标识写作"环:环内序号"，例如 `3:7`。

半径取自控制台设计稿的绘图尺寸：环中心半径从 4.0 到 25.75，环宽 2.75，灯环半径 29.15。`Zone.radius` 是除以第 7 环外缘半径后的归一化半径，给空间化使用。

## 去抖的实现

去抖按压力图到达的时刻计算：每个区记住"读数开始与当前状态不同"的时刻，持续达到 `occupy_hold`（放下）或 `release_hold`（拿起）才翻转状态并产生事件，事件时刻是确认的那一帧的时刻。中途读数回到原状态，计时清零。没有新压力图时状态不变，所以控制器断线不会让石头"被拿起"。当前初值是放下 40 ms、拿起 80 ms，尚未在真机上调过（见 `TODO.md`）。

虚拟垫子同样经过去抖。它像控制器一样持续产生压力图，所以点击之后约 40 ms 才出现"放下"，与真机一致。虚拟石头的压力固定为 0.5（约等于读数 2048）。

## 声音引擎的实现

引擎通过 `sound/backend.py` 的 `Backend` 接口发出抽象指令：建立和释放一个模式实例的混音结构、设置它的交叉淡化增益和全局参数、开始/修改/淡出/强制释放一个声部、加载和释放素材、设置总输出。声部编号由引擎从 1000 开始分配，正好可以直接用作 scsynth 的节点号。每条指令都带执行时刻：意图里的时刻加上配置的输出延迟 `sound.output_latency`（30 ms）；定时事件晚于 `sound.late_tolerance`（50 ms）就丢弃。

`RecordingBackend` 是不发声的实现：照单记录指令，并模拟合成器服务的通知——淡出的声部在淡出时长之后结束，单次声音在固定的 2 秒后结束，`simulate_restart()` 模拟合成器服务重启。测试用它检查对账和调度的结果。

已发出的定时事件标识保留 30 秒用于去重。合成器服务重启后引擎调用 `rebuild`：清空声部表，重新设置总输出、建立各实例的混音结构、恢复全局参数，并调用 `on_rebuild` 回调（例如素材库重新加载素材）；下一拍的对账把所有持续声部重新开始。

引擎交给合成器接口的增益有三组：单声道声源用的一组，以及立体声声源左右声道各一组。立体声声源不定位时，左右声道放在房间的左前 330° 和右前 30°（立体声布局下即原样的左右声道）；定位时放在位置两侧各 10°。

空间化公式见 `sound/spatial.py` 的说明：方向上在相邻两只音箱之间等功率分配，再按半径与均匀分布混合，最后归一到等功率。预设布局有立体声（左 330°、右 30°）、四声道（左前 315°、右前 45°、右后 135°、左后 225°）和八声道（0° 起每 45°）。

## 设置与启动

设置保存在数据目录的 `settings.json`，结构与状态树的 `settings` 一致。读取时逐项校验，非法或无法读取的项回到默认值并写一条警告；修改经过 `Settings.update` 逐项校验，任何一项非法就整批拒绝。写入先写同目录的临时文件、`fsync` 后再 `os.replace`，断电时要么是旧文件、要么是新文件。

声音相关的设置（总音量、音箱布局、朝向）变化时，运行管理把应用动作放进声音化的命令队列，在下一拍由节拍线程交给声音引擎。素材库位置变化时重新检查所有编排的素材。启动时播放设置里的默认编排；它不存在时改用第一份能找到的编排，并写一条警告。

## 设备连接与垫面信号

串口协议、选口规则和打开方式沿用第一版：921600 波特；Mac 上只看 `/dev/cu.*`，Linux 上看 `ttyUSB*`、`ttyACM*`、`/dev/serial/by-id/*` 并排除板载 UART；打开时 DTR、RTS 置低；收到第一帧 `S:` 才算控制器就绪并开始发灯光帧，就绪后的第一帧灯光发两次。打不开或没有找到串口时每 2 秒重试；连着但 5 秒没有 S 帧时关掉重开。校验失败的帧丢弃并计数。链路状态每 0.5 秒写入 `status.mat`。

垫面信号把 256 个接线读数按预先算好的索引表取成 224 个区域，再做校准（无效读数 −1 当 0、可选反相、除以满量程）。索引表由第一版的映射规则逐步照搬生成：整体先做扇区镜像，外环直接取镜像后的扇区，内环从镜像后的奇数接线扇区读回，最后整体旋转 `sector_offset` 个扇区。需要注意的是，内环在第一版里经过两次镜像，结果其实没有被镜像：内环第 j 个有电极的接线扇区 2k 落在逻辑扇区 2k+1，而外环是反向的。新版照搬了这一行为，是否符合实物需要在真机上核对（见 `TODO.md`）。

灯光引擎把各层按优先级从低到高、按不透明度合成到黑底上；施加偏移时逻辑位置 k 的颜色写到物理灯珠 (k + `led_offset`) mod 108。

## 系统监测

探针都只读，任何一个失败（开发机上没有 JACK、不是树莓派、没装 nmcli）都返回"未知"，不沿用旧值：

| 项目 | 来源 |
|---|---|
| 音频服务是否运行、打开的设备、采样率、缓冲 | 在 `/proc` 里找到 `jackd` 进程，读它的命令行（`-d alsa -d hw:… -r -p -n`） |
| USB 声卡、实际输出设备 | `/proc/asound/cards`，把 JACK 打开的 `hw:` 设备对应到声卡名字；名字或描述里有 USB 即为 USB 声卡 |
| 卡顿次数 | 最近一小时 systemd journal 里 jackd 的 xrun 记录数 |
| 合成器服务 | `/status.reply`：是否在线、音色是否加载、采样率、平均与峰值负载（另保留最近 60 秒的负载曲线） |
| 机器 | `/sys/class/thermal`、`vcgencmd get_throttled`、`/proc/meminfo`、数据目录所在磁盘、`/proc/uptime`、`/proc/device-tree/model` |
| 网络 | `nmcli` 当前连接、出口地址、`tailscale status --json` |

状态指示的规则（按顺序，第一条成立的即为结果）：

1. 声音：合成器服务没有响应 → 异常；没有连接合成器服务（`--no-synth`）→ 未知；音色没有加载 → 异常；Linux 上 JACK 没有运行 → 异常；期望 USB 而实际输出设备不是 USB 声卡、或找不到 USB 声卡 → 异常；采样率与期望不同 → 需要注意；当前编排缺少素材 → 需要注意；负载峰值超过 85% → 需要注意；最近一小时有卡顿 → 需要注意；否则正常。
2. 垫子：使用虚拟垫子 → 正常；控制器未连接 → 异常（原因来自设备连接，例如"没有找到控制器的 USB 串口"）；实测帧率低于 20 → 需要注意。
3. 网络：没有任何出口地址 → 需要注意（装置离线也能演奏，所以不算异常）。

逐声道测试音由 `POST /api/audio/test-tone` 触发：在节拍线程里让合成器服务在指定的硬件声道上放 1 秒 440 Hz 的正弦波，绕过混音结构和系统音量。

## 录制

录制的状态机在声音化的节拍线程里推进（`Recorder.on_beat` 挂在每拍末尾）。按下录制后：检查剩余空间（按总输出 24 位、分轨 32 位浮点估算，需要能录 10 分钟另加 200 MB 余量，否则拒绝并说明原因）；在 0.2 秒后开始录音（给合成器服务打开文件的时间），同一时刻开始 3 秒倒计时；打板在录音开始后正好 3 秒，提示音由合成器服务按时间戳播放，灯光是录制系统层（优先级最高）。录制中每 0.5 秒检查一次空间，少于 1 分钟时自动停止；合成器服务中断时也停止。停止后写好录制信息，刷新录制列表（`catalog.recordings`）。

一次录制的文件夹 `<录音保存位置>/<YYYY-MM-DD_HHMMSS>_<编排标识>/`：

| 文件 | 内容 |
|---|---|
| `master.wav` | 总输出（硬件输出总线 0…N−1，经过系统音量和限幅），24 位整数 WAV |
| `stems/<总线>.wav` | 各环总线、分组总线和效果返回 `fx`，在模式总处理之前、乘过交叉淡化增益；可能超过 0 dBFS，所以是 32 位浮点 WAV |
| `session.jsonl` | 每行一条，带系统时间 `t`：`start`、`pressure`（最多 30 次/秒，压力 × 1000 和有石头的区域）、`event`（放下、拿起）、`sound`（持续声部与全局参数，变化时）、`events`（交出的定时事件）、`light`（灯环颜色，最多 10 次/秒）、`slate`、`stop` |
| `info.json` | `startedAt`（带时区的开始时间）、`startSystemTime`、`slateOffsetSeconds`（打板在录音中的位置，固定 3 秒）、`slateSystemTime`、编排、声道数、采样率、格式、开始时的设置、文件清单、`duration`、`endedAt`、`stopReason` |

没有连接合成器服务（`--no-synth`）时也能录制，只产生会话数据和录制信息，`audio` 为 false，不建 `stems/` 目录；文件清单只列实际开始录制的文件。下载接口把整个文件夹边打包边输出为不压缩的 zip，不需要临时文件。
