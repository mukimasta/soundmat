# Synth

本文说明合成器服务（scsynth）这一侧的工程实现：音色怎样编写和编译，主机程序怎样在 scsynth 里搭建混音结构、发出带时间戳的指令、发现 scsynth 重启，以及怎样不上真机离线渲染一份编排。声音引擎的系统机制见 `system_design/SOUND_ENGINE.md`，Python 侧的引擎实现见 `HOST_PROGRAM.md`。

主机程序这一侧在 `soundmat/sound/scsynth.py`，分两层：`ScsynthCommands` 把声音引擎的指令翻译成 scsynth 的 OSC 指令，并给节点、总线和缓冲区编号记账；它不关心指令怎样送到合成器服务，只经两个出口交出——`send`（立即执行）和 `schedule`（在某个时刻执行）。`ScsynthBackend` 是实时连接，用 UDP 实现这两个出口，并负责查询状态、接收通知（下文「时间戳」「连接、重启与通知」「电平」）。离线渲染用同一套翻译、换掉两个出口（「离线渲染」）。

## 运行 scsynth

树莓派上 scsynth 是独立的系统服务，由 systemd 启动（JACK 之后，见 `DEPLOYMENT.md`），主机程序只通过 UDP 57110 端口与它通信（配置 `[synth]`）。这样主机程序重启（部署新版本、出错后被拉起）时声音链路不中断，scsynth 出错时由 systemd 单独重启、主机程序发现后重建，两边各自恢复。

开发机上为了一条命令就能运行，`uv run soundmat` 启动时先向配置的地址发 `/status`：有回应就直接连（systemd 服务、手动启动的都算）；没有回应、地址在本机、并且不在 systemd 下运行时，自己启动一个 scsynth，参数与 `scripts/scsynth-dev.sh` 相同、声道数取当前音箱布局，退出时一起关掉（`soundmat/sound/scsynth_process.py`）。在 systemd 下从不自己启动，免得和 scsynth 服务抢端口。scsynth 的位置依次是环境变量 `SOUNDMAT_SCSYNTH`、PATH 里的 `scsynth`、`/Applications/SuperCollider.app`。想单独看 scsynth 的输出时，也可以先用 `scripts/scsynth-dev.sh [声道数]` 手动启动：优先用 `/Applications/SuperCollider.app` 里的 scsynth，否则用 PATH 里的；macOS 走 CoreAudio 的默认输出设备，不开输入（`-i 0`，避免输入输出设备采样率不一致），采样率 48 kHz（`-S 48000`，设备设不到时 scsynth 报错退出，需在"音频 MIDI 设置"里改）。scsynth 的硬件输出声道数（`-o`）不能少于音箱布局的声道数。

主机程序默认连接 scsynth；连不上时照常运行、什么都不发，等 scsynth 出现后自动接上。`--no-synth` 改用只记录指令的声音引擎。

云端和 CI 没有声卡：可以安装 `jackd2` 和 `supercollider-server`，用 `jackd -d dummy -r 48000` 起一个虚拟声卡，再启动 scsynth。`tests/test_scsynth.py` 里连真实 scsynth 的两个测试（真实的 Jam、录音打板）只在设置 `SOUNDMAT_LIVE_SCSYNTH=1` 并且本机能连上 scsynth 时运行，CI 里打开。它们会清空 scsynth 的节点树、发声并录音，所以默认不运行，免得打断开发机上正在试听的合成器服务。`tests/test_render.py` 里渲染一小段的测试用 scsynth 的非实时模式（不连合成器服务，也不出声），本机找得到 scsynth 和编译好的音色就运行，CI 编译音色的那一项里也跑。

## 音色

音色源码在 `instruments/`，用 SuperCollider 语言编写：

| 目录 | 内容 |
|---|---|
| `lib/common.scd` | 所有音色共用的约定：空间化输出 `~smOut`、持续声部的包络 `~smGateEnv`、按声道数命名 `~smDef` |
| `lib/jam_common.scd` | 第一版 Jam 音色共用的函数（与 web 原型 Tone.js 对齐） |
| `lib/tone.scd` | 网页原型（Tone.js / Chrome Web Audio）几样基本构件的对应实现：滤波器、三种噪声、干湿比、混响 |
| `lib/pool_common.scd` | 声池音色共用的网页主效果链（`~poolOut`） |
| `players/` | 素材回放：单声道 / 立体声，带或不带保时长变调 |
| `ambient/` | Ambient 的合成音色（管风琴 drone、马林巴） |
| `pool/` | 声池（《冥想》）的底音、低音、和声、音符、钟声、天气、雷、水滴、鸟鸣 |
| `jam/` | Jam 的和声铺底、旋律、贝斯、鼓 |
| `system/` | 混音结构：模式总处理、共用效果、总输出、测试音 |

SynthDef 的声道数在编译时固定，所以每个音色按 2、4、8 声道各编译一份，名字后缀声道数（`marimbaNote_2`）。主机程序按当前音箱布局的声道数选用。编译：`uv run python scripts/compile_instruments.py`（等价于 `sclang instruments/build.scd`），产物在 `instruments/compiled/`，不进仓库，部署时随程序同步。树莓派上不需要 sclang。脚本按 `SOUNDMAT_SCLANG`、`PATH`、`/Applications/SuperCollider.app/Contents/MacOS/sclang` 的顺序找 sclang；只在 Linux 上默认设置 `QT_QPA_PLATFORM=offscreen`（无桌面也能运行），macOS 版 SuperCollider.app 只带 cocoa 平台插件，不能设置 offscreen。

### 音色的约定

1. 音色把信号交给 `~smOut.(干声, 效果发送)`。单声道信号按增益 `g0`…`g{N−1}` 分配到各只音箱；立体声信号左声道按 `gl*`、右声道按 `gr*` 分配。增益带 50 ms 平滑。干声写到 `out`（声部所在的总线），效果发送写到 `fx`（共用效果的发送总线）。
2. 持续声部用 `~smGateEnv`：`atk` 淡入、`gate` 置 0 时按 `rel` 淡出并释放。单次声音自己结束（`doneAction: 2`）。
3. 素材回放的参数：`buf`、`loop`（持续 1、单次 0）、`amp`（dB）、`rate`、`rateVar`、`lpf`、`hpf`、`revSend`，变调版多 `semitones`、`winSize`。主机程序按素材的声道数和是否有 `semitones` 选择 `sm_play_mono` / `sm_play_stereo` / `…_tune`。
4. 不认识的参数会被 scsynth 忽略，所以编排可以随意给音色加参数，只要音色里有同名控制。

第一版音色的改动：输出从固定的立体声改为多声道空间化；和声铺底从"保持 hold 秒后自己结束"改为持续声部（和弦层靠 gate 释放，`rel` 1.5 秒），因为新版的和声是带开始时刻的持续声部；`pan`、`Balance2` 去掉，方位由空间化决定。

### 网页原型的对应实现

《冥想》的音色要和网页原型听起来一样，所以 `lib/tone.scd` 按 Tone.js 15 与 Chrome 的源码逐项对齐，而不是凭听感调：

1. **滤波器**：Web Audio `BiquadFilterNode` 的系数公式，用 `SOS` 实现。低通、高通的 Q 在 Web Audio 里是分贝（Tone.Filter 默认 1 dB），带通的 Q 才是线性的。
2. **噪声**：白噪声与 `Math.random() * 2 − 1` 相同；粉红噪声用 SC 自带的 `PinkNoise`，按用到的频段补偿电平（实测比 Tone 照 Paul Kellet 方法算出的低 3.3–4.8 dB，例如风 ×1.55、雨 ×1.68，误差 ±0.5 dB；照抄 Tone 的算法要十几个 UGen）；褐色噪声照抄 Tone（截止约 150 Hz 的一阶低通，×3.5）。
3. **干湿**：Tone 效果的 wet 是等功率交叉（干 cos、湿 sin）。
4. **混响**：Tone.Reverb 的冲激响应是指数衰减的白噪声，衰减 60 dB 的时间是 ln(1000)·ln(decay+1)/ln(200)（decay 7 时 2.71 秒），Web Audio 的卷积按冲激响应的均方根归一化，每个声道的能量只和缓冲长度有关：(10^(−58/20) × 44100/48000)² × (decay + 0.01) × 48000（decay 7 时 0.450）。卷积在 Pi 3B 上太贵，改用两种便宜的结构按同样的衰减和能量校准：主混响每个声道一个 `FreeVerb2`（不加阻尼；FreeVerb2 把两路输入相加，所以每个声道只给一路，左右轮流用它的左、右两个混响，互不相关；能量按 100 Hz–6 kHz 对齐，因为 FreeVerb 在 12 kHz 以上弱一些）；单声道进立体声出的小混响（水滴、远处的音）用 4 个梳状滤波器加 3 个全通，延迟和 FreeVerb 错开——水滴的混响之后还要进主混响，两级结构相同时共振峰会叠在同样的频率上。实测衰减时间和能量与网页一致；对单一频率，两种混响的响应都随频率随机起伏（标准差 5.5 对 5.2 dB），统计上一致。只在 48 kHz 下校准过。测 FreeVerb 的冲激响应时冲激不能放在第 0 个采样：它初始化时先把第一个采样算一遍，会算两次。
5. **单声道与空间化**：网页上单声道信号同时送到左右两个声道；引擎的空间化是等功率的，所以单声道音色 ×√2，总功率与网页一致。噪声、混响这类立体声信号左右原样。

网页的主效果链（混响 → 8 kHz 低通 → 压缩器 → ×0.85）拆在 `lib/pool_common.scd` 里：低通是线性的，在每个高频成分多的声部上先做；干声写到声部的总线，混响在共用效果 `sm_fx_pool` 里加回；Chrome 的压缩器在这么低的电平下几乎只是自动补偿的 +0.8 dB，并成固定增益。CPU（按离线渲染的耗时折算成 Pi 3B 的负载，见「离线渲染」）：冥想空垫子约 12%，每环一颗约 30%，放满石头约 35%，低于放满石头的 Jam（实测 46%）。

## 节点树与总线

```text
根（0）
├── 组 100：模式实例
│   ├── 实例组（每个模式实例一个；切换编排时旧的一组还要淡出 0.3 秒，这期间新旧两个并存）
│   │   ├── 声部……（加在组头）
│   │   ├── 共用效果（sm_fx_freeverb、sm_fx_jam 或 sm_fx_pool）：读效果发送总线 → 写效果返回总线
│   │   └── 模式总处理（sm_mode）：各总线 × 增益 + 效果返回 → Lo-Fi → 编排电平 → 总输出总线
│   └── ……
└── 组 101：总输出（sm_master）：系统音量 → 限幅（−1 dB）→ 硬件输出 0…N−1
```

每个模式实例分配：模式声明的每条总线（最多 12 条）、效果发送总线、效果返回总线，各 N 个声道；全局还有总输出总线和一条从不写入的静音总线（`sm_mode` 未用的输入指向它）。私有总线从 128 号开始（假设硬件输入输出合计不超过 128 个声道），用首次适应分配，释放推迟 1 秒，避免还在淡出的节点写到被重新分配的总线上。主机程序分配的节点号从 1999999999 往下递减，与引擎分配的声部号（从 1000 往上）不会相遇。主机发给 scsynth 的时间戳按墙钟换算。树莓派没有电池时钟，开机联网校时会让墙钟一下跳几分钟，而 scsynth 要在约一分半钟里才逐渐对齐自己的时钟（实测），这期间带时间戳的指令在它看来都在很久以后，会被压住。所以开机时先等校时、再启动声音，之后这次开机不再校时（`system/clock/`，`DEPLOYMENT.md`「时钟」），主机程序本身不处理时钟跳变。两边的编号都**永不重复使用**，重连、重建混音结构之后也接着数：清空节点树时，已经发出、排在未来时刻（定时声音提前 0.15 秒以上）的指令还在 scsynth 的队列里，会在清空之后照常执行；如果新的混音组和旧的同号，这些指令建出的声音就落进新组、成为主机程序不知道的节点，没人释放。编号不重复，它们指向的组已经不存在，scsynth 报"组不存在"后丢弃。

全局参数里，`bus.<总线>` 设置该总线在 `sm_mode` 里的增益，`fx.<参数>` 设置共用效果，其余（`cutoff`、`drive`、`lofiGain`）交给 `sm_mode`。`cutoff` 达到 18 kHz（默认 20 kHz）时低通被旁路：低通截止接近奈奎斯特频率时会失稳，第一版也把上限定在 18 kHz。

## 时间戳

引擎每一拍发出的指令先按执行时刻分组暂存，一拍结束时整批发出：同一时刻的指令放进一个 OSC bundle（超过 8 KB 拆成几个）。时刻是系统时间（单调时钟），发送时换算为墙钟时间 `time.time() + (时刻 − time.monotonic())` 作为 bundle 时间戳；每次发送都现算，开机后 NTP 校时让墙钟跳变也不受影响。主机程序与 scsynth 在同一台机器上，共用系统时钟。时刻已到的指令用"立即执行"的时间戳，scsynth 不会为它们记录迟到警告。

## 连接、重启与通知

主机程序每 0.5 秒发一次 `/status`，并在已连接时用 `/n_query 100` 确认根组还在。

1. 第一次收到 `/status.reply`：发 `/notify 1` 订阅节点结束通知，`/d_loadDir` 加载编译好的音色；收到 `/done /d_loadDir` 后用 `/g_freeAll 0` 清空整棵节点树（主机程序重启时 scsynth 照常运行，上一次的节点还在），再建立组 100、101，报告"重新启动过"。引擎据此重建混音结构、重新加载素材，下一拍对账恢复所有持续声部。
2. `/n_query` 回答"找不到节点"：scsynth 在两次查询之间重启过，按第 1 步重新接上。
3. 发出的 `/status` 查询超过 2 秒没有回答：视为离线，不再发送任何指令，等它回来后按第 1 步接上。判断的是"问了没回"，而不是"多久没收到回复"：查询由节拍线程发出，主机自己卡住几秒时根本没有发查询，不能因此把合成器服务当成停了、重建混音结构、停掉录音（2026-10-18 在 Pi 3B 上发生过）。
4. `/n_end` 通知某个声部结束：如果是引擎的声部，转告引擎移出声部表。

素材用 `/b_allocRead` 读入缓冲区；用到缺失素材的声部不发送，并立即当作结束告诉引擎。

## 电平

`sm_mode` 对每条输入总线、`sm_master` 对总输出，用 `SendPeakRMS` 以 10 次/秒回报峰值（`/sm_peak`）。主机程序把总输出各声道和每环的峰值整理成控制台的 `levels` 消息：每环分左右两侧，左侧取方位在 180°–360° 的音箱、右侧取 0°–180° 的音箱（正前和正后两侧都算），超过 1 秒没有更新的值不算。

## 录制

`sm_mode` 除了把各输入相加，还把每条输入（乘过总线增益和编排电平）加到一条按总线名分配的全局分轨总线上，效果返回加到全局的 `fx` 分轨总线；未用的输入指向一条废弃总线。所以分轨与模式实例无关，录制中切换编排时新旧两组一起汇入，录音不中断。

开始录制时，每个文件分配一个缓冲区（`/b_alloc` 65536 帧 × N 声道），用 `/b_write … "wav" 格式 0 0 1` 以流式写入的方式打开，再在稍后的时刻于组 101 末尾启动 `sm_rec`（`DiskOut`）：总输出从硬件输出总线读取，分轨从全局分轨总线读取。异步命令按顺序执行，所以分配、打开、开始的次序是保证的。停止时在同一个 bundle 里依次释放录制节点、`/b_close`、`/b_free`。打板提示音 `sm_slate` 与录音节点同一个时间戳、在它们之后加到组 101 的末尾，直接写到硬件输出（不经过系统音量和限幅）：音箱照样播出，但录音节点在它写入之前已经读过硬件输出，所以提示音不进录音，录音正好从这一刻开始。

## 离线渲染

`scripts/render.py` 把一份编排在一张石头时间表上的演奏渲染成 WAV，不连合成器服务，也不出声。用来对比音色（例如与网页原型）、调编排电平（例如 Pi 5 上的京都岚山）、估算合成器服务的负载，不必每次都上真机：

```bash
uv run python scripts/render.py meditation scripts/scenes/twenty_stones.json out.wav --stats
```

时间表是 JSON，时刻以秒计、从渲染开始算；`scripts/scenes/` 里有下文折算负载用的几张（空垫子、每环一颗、20 颗、放满石头的 Jam）：

```json
{"duration": 150,
 "stones": [{"ring": 0, "slot": 3, "on": 2.0, "off": null}],
 "control": [{"on": 2.0, "off": null, "pressure": 3000}]}
```

`ring` 是主机程序的环号（由内到外 0–7），`slot` 是环内序号，`off` 为 `null` 表示一直放着。`control` 可省略，是控制区（Jam 的内两环）上额外的压力，和编排、配置里的压力一样用 ADC 原始读数之和，平均分到各控制区；几段同时有效时相加，放在控制区上的石头照常计入。0 到 1 之间的压力多半是误写成了归一化值，直接报错。

**怎样运行。** 主机程序的声音部分按运行管理的方式组装、原样运行：感知（石头按虚拟垫子的压力放下，经过真实的去抖）、声音化与模式、声音引擎、素材库。只是不启动线程，按模拟时间以 `sound.tick_hz` 一拍一拍地调用：每拍先把这一刻的压力图交给感知，再调用声音化的 `on_beat`。合成器接口换成乐谱后端，它继承 `ScsynthCommands`，立即执行的指令记在当前的模拟时刻，定时指令在一拍结束时记入（同一时刻的先后与实时连接发出的顺序一致），所以乐谱里的指令和实时运行时发给 scsynth 的完全相同。素材照常经素材库加载，`/b_allocRead` 进乐谱，用素材的编排（京都岚山）也能渲染。乐谱写成 scsynth 非实时渲染的格式：一串 OSC bundle，每个前面加 4 字节的长度；时间标签是从乐谱开头算起的秒数，32.32 定点，不加 NTP 纪元的偏移；同一时刻的指令放进一个 bundle（超过 8 KB 拆开）；最后在时长处放一条 `/c_set 0 0`，渲染到这里为止。然后运行 `scsynth -N 乐谱 _ out.wav 48000 WAV float -o 声道数 -i 0`，其余参数与装置上的 scsynth 服务一样用默认值。macOS 上 SC 3.14 的 scsynth 写完文件后会以 SIGSEGV 退出（返回 −11），文件是完整的，所以按文件是否写出来判断成败。

**声部什么时候结束。** 非实时渲染不回报 `/n_end`，要由乐谱后端模拟，否则引擎的声部表只增不减，预算很快被占满。音色的长度直接从编译好的 SynthDef 里算：找出会释放整个声部的 UGen（`doneAction: 2` 的 `EnvGen`、`Line`、`XLine`），用这个声部实际收到的参数求出包络的总时长（参数之间的加减乘除、`max`、`Select` 都照算），取最早结束的一个；有释放点、门开着的包络（持续声部的淡入淡出）要等引擎让它淡出，淡出的声部在淡出时长之后结束。单次播放的素材按文件长度和播放速度算。音色改了长度，这里自动跟着变；算不出来的单次声音（例如长度取决于随机数）按 2 秒估算并在输出里列出，不会自己结束的单次声音也会列出。

**输出。** scsynth 的报错；渲染用时；同时存在的声部最多几个（引擎的声部表，含淡出中的）和配置的预算；引擎计数（让位、因预算放弃、迟到丢弃、重复丢弃、重启）；缺少的素材；运行中记下的警告和错误。`--stats` 另外打印 BS.1770 的整体响度（LUFS；四声道、八声道各声道的权重都是 1）、采样峰值和每 10 秒的平均电平（RMS）。引擎让一个按时刻开始的声部让位时，释放同样排在提前量之后，这期间它可能已经自然结束，scsynth 报"找不到节点"：装置上也一样，无害，单独计数，不算报错。同一种子（`--seed`，默认 1）的乐谱逐字节相同；scsynth 里的噪声每次运行不同，所以音频只在统计上一致。

其余选项：`--channels 4` 或 `8` 按预设的四声道、八声道布局渲染；`--level` 代替编排里的整体电平，调电平时不用改编排文件；`--volume` 是总音量，默认取设置的默认值 0.8；`--sound` 指定素材库；`--score` 留下乐谱文件。声部预算默认不限（对照没有预算的网页原型时用），`--real-budget` 按配置的预算让位和放弃，和装置一样；不限时声部数超过配置的预算会有提示，这时声音和负载以加 `--real-budget` 的结果为准。

**折算负载。** 非实时渲染和实时运行的 scsynth 一样只用一个线程，合成本身的用时占音频时长的比例可以折算成装置上合成器服务的负载。启动 scsynth、加载音色和素材的用时另外渲染一份只有加载的乐谱量出来、扣掉（京都岚山的素材要零点几秒）。折算系数按 Jam 对照：放满石头的 Jam（`scripts/scenes/jam_full.json`，加 `--real-budget`）在开发用的 Mac（M1 Pro）上是音频时长的 1.8%（几次在 1.7–1.9% 之间），Pi 3B 上实测 46%，约 ×25。移植《冥想》时用的 ×32 偏大：当时的临时渲染器把没有列出长度的单次声音一律按 3 秒算，Jam 的音符（rhodes 约 1.6 秒）在引擎里多占了将近一倍的时间，旋律声部的预算被已经结束的声音占着，少演奏了约七分之一的音符，渲染出来只有 1.4%。换一台开发机或对照 Pi 5 时，按同样的方法重新对照。
